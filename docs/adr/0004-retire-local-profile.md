# ADR-0004: 废除本地 profile.md，业务词表随 skill 分发

- **状态**：已接受
- **日期**：2026-10-24
- **取代**：ADR-0001

## 背景

ADR-0001 把环境事实拆成两层：`~/.lts-cli/config.json` 给 CLI（含明文 AK/SK），`~/.lts-cli/profile.md` 给 AI（业务词表），并声称"由文件边界强制隔离"。

这个隔离不成立。两层在同一个目录、同一个账号、同样的权限（目录 0700、文件 0600）：**AI 能读 profile，就必然能读 config。** 更糟的是 `SKILL.md` 直接指示 AI `cat ~/.lts-cli/profile.md`——等于给它一个进入凭证目录的正当理由。一次手滑的 `cat ~/.lts-cli/*`、`ls -la`、`Get-ChildItem` 就会把 AK/SK 送进上下文，而凭证泄漏不可撤回，只能轮换。

也就是说，ADR-0001 防的是"AI 主动越界"，而它实际引入的是"AI 被邀请进入"。把纪律当机制，是这份 ADR 最根本的错误。

另一半问题也没解决：`profile.md` 里的业务词表本身就是第二份会过期的真相来源。

## 决策

1. **废除 `profile.md`。** `lts-cli init` 不再生成任何词表文件。发现 2.0 遗留的 `~/.lts-cli/profile.md` 时打印一行提示，**不代删**——那是用户手写的文件。
2. **词表随 skill 走。** 约定路径 `<skill目录>/references/vocab.md`，可选、默认不存在。它不在凭证目录里，AI 读它不需要靠近 AK/SK。
3. **主路径改为运行时枚举。** `SKILL.md` 教 AI 用管道 SQL 列出候选值（`* | SELECT appName, count(*) AS cnt GROUP BY appName`），拿候选表请用户指认，而不是查静态词表。词表只是"想省这一步"时的可选缓存。
4. **词表默认不进版本控制。** `.gitignore` 用白名单排除 `references/` 下除两份内置文档之外的一切，避免用户填了内部代号再 fork/PR 时把内部信息带出去。
5. **`SKILL.md` 新增铁律：不碰 `~/.lts-cli/`。** 不读、不 `ls`、不通配符展开；要看配置用 `lts-cli config --list`（已脱敏）。这是文档层收口，不是机械保障——真正的保障是第 1、2 条让 AI 没有理由进入该目录。

## 取舍

- **代价**：换机器、换 AI 工具要重填词表；用 `npx skills --copy` 或插件方式安装时，升级会整目录替换，词表需要自行备份（`npx skills` 默认软链到一份 clone，词表作为未跟踪文件可在 `git pull` 中存活）。
- **收益**：AI 不再有任何正当理由进入存着明文 AK/SK 的目录；真相来源收敛到运行时，不再有第二份会过期的字段表/应用名清单。
- **边界**：不引入 keychain。凭证仍以 0600 落盘在 `~/.lts-cli/config.json`。keychain 会带来原生依赖与跨平台构建负担，对这个体量的工具是过度工程；等出现多机、多人共享需求时再单独决策。

## 被否方案

- **保留双轨，只加强文档警告**：权限相同这一事实不会因为警告而改变。
- **全部删除词表**：能力上可行（取值可实时枚举），但"团队黑话"这类 API 拿不到的信息会彻底无处安放。
- **把词表塞进 `config.json`**：重新把业务事实和凭证混在一处，正是本次要消除的风险。
- **放进插件数据目录**（如 Qoder 的 `QODER_PLUGIN_DATA`，官方称可跨升级保留）：只有单一工具提供，跨工具不一致，不能作为主方案。
- **自建 `lts-cli install-skill` 命令**：分发这件事已经由 `npx skills` 标准化（`add` / `update` / `remove` / 多 agent 适配），重复实现是维护负债。

## 适用条件与失效条件

当前成立。若 LTS 提供服务端可存的业务元数据（日志流标签、命名空间），词表可以彻底退休，业务词义改为随日志流存储。若将来出现多人共享同一套词表的需求，再评估是否需要独立的同步通道。
