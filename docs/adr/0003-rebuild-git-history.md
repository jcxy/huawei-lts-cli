# ADR-0003: 2.0.0 重置提交历史

- **状态**：已接受
- **日期**：2026-10-24

## 背景

1.x 的提交历史（10 个 commit）包含只适用于作者所在环境的示例数据：具体业务系统名、日志组与日志流 ID、内部字段名。这些内容按 ADR-0001 已从工作树中移除，但仍留在历史里，任何人 `git log -S` 都能翻出来。此外部分提交信息存在编码损坏（中文乱码）。

当时的事实：仓库 0 fork、0 PR、0 release、2 star，无任何外部引用。**这是重写成本最低的时刻，也是最后的时刻。**

## 决策

在 2.0.0 代码改造全部完成后，以工作树为准重建历史：

1. 本地保留 `backup/pre-2.0.0` 分支（**不推送**）作为回滚点；
2. `git checkout --orphan` 建立新的初始提交，工作树为清理后的完整 2.0.0 状态；
3. force push 覆盖 `main`；
4. 旧历史不再保留。

## 取舍

- 代价：失去 10 条提交历史，以及本次改造期间的逐条提交粒度（仅存在于本地备份分支）。
- 收益：公开仓库从第一秒起就是干净的；首提交按 Conventional Commits 重新写，不再继承乱码的提交信息。

## 被否方案

- **`git filter-repo` 精确剔除**：10 个 commit 里几乎每个都命中目标内容，剔除后剩余结构与重建差异极小，但需要额外工具与更长的验证链。
- **只改 HEAD、保留历史**：零风险操作，但内部命名体系永久公开，且 GitHub 会继续通过 commit SHA 提供访问。
- **新建仓库并归档旧仓**：star 与仓库地址全部丢失，对已有引用不友好，收益与第一种方案相当。

## 适用条件与失效条件

**仅在 0 fork / 0 PR / 无外部引用时成立**，当前满足。一旦仓库产生 fork 或外部引用，必须改为 `filter-repo` 精确剔除，并提前通知持有 fork 的一方——此时强制重写历史会破坏他人的工作副本。
