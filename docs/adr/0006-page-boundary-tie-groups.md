# ADR-0006: 页边界上的同纳秒组

- **状态**：已接受
- **日期**：2026-10-27
- **关联**：[ADR-0002](0002-cursor-pagination.md)、[ADR-0005](0005-full-scan-invariants.md)

## 背景

ADR-0002 / 0005 确立了游标分页：取上一页末条的 `line_num`，配 `search_type=forwards` 续读。但游标是**排他**的，而 `line_num` 在纳秒级并不唯一（ADR-0005 已实测确认）。

两者叠加会产生静默丢数据：一组同 `line_num` 的日志正好被页边界切开时，第一页只带走组内前几条，下一页从该 `line_num` 续读会跳过**整个组**，剩下的兄弟记录再也读不到。

实测（2026-10，cn-south-1，`acerp-wrs-service`，OD26102310003916）：

- 单页 `-l 100` 查得到 18 条；
- `--all -l 5` 只拿到 17 条，漏掉 line_num=1793063126155000000 的兄弟记录；
- 服务端全程不报错，`isQueryComplete` 仍为 true。

## 决策

1. **续读游标取末条的前一格**：正序 `L-1`、降序 `L+1`（`line_num` 是纳秒整数）。这样下一页从同值组的组头开始读，整组都会回来。
2. **按「line_num + content + labels」跳过本页已收走的组内条目**，而不是按 `line_num` 去重——`line_num` 不唯一，只按它去重会丢掉同纳秒的真实日志。签名计数保留重数，同纳秒同内容的真实重复日志也会按条数保留。
3. **请求条数加上边界组大小**（`pageSize + boundarySize`），保证每页仍有 `pageSize` 条新数据，不让修补变成 2 倍请求数。
4. **游标推不动时的止损**：整页都是回放且不满一页 = 已经到底，正常结束；整页都是回放且页满 = 同值组大于一页，逐次放大页面试图越过，直到 5000 上限仍无法推进才标记 `truncated`。

## 取舍

- 收益：`--all` 在存在同纳秒日志时不再静默少读；升降序实测均能取全（18/18，无重复、无遗漏）。
- 代价：续读请求带上一页末条的前一格，语义不如「从末条继续」直观；边界组的签名计数需要跨页累计，读代码时必须先看 `pagination.ts` 顶部的注释。

## 被否方案

- **按 `line_num` 去重兜底**：会丢掉同纳秒的真实日志（ADR-0005 已否决）。
- **用 `backwards` 从同一游标补读**：实测游标在正反两个方向都排他，从 `L` 出发无论 `forwards` / `backwards` 都拿不到组内剩余条目。
- **改用 offset**：服务端不存在 offset 语义（ADR-0002）。

## 适用条件与失效条件

若服务端开始保证 `line_num` 唯一，或提供「包含边界」的游标语义，可以退回直接取末条 `line_num` 续读。判断依据只能是实测：同一窗口、同一游标，比较 `L` 与 `L±1` 两种续读方式对同值组的返回结果。
